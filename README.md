# IDX Exchange 2026 Summer Internship Project

# California Residential Property Automated Valuation Model

## Overview

This project develops an **Automated Valuation Model (AVM)** for estimating the closing prices of California single-family residences using CRMLS sold-property data.

The project follows an end-to-end data science workflow, including:

- exploratory data analysis;
- data preprocessing and missing-value handling;
- chronological train/validation/test splitting;
- feature engineering;
- baseline and tree-based regression models;
- XGBoost hyperparameter tuning;
- expanded model evaluation using R², MAE, MAPE, and MdAPE;
- deployment of the trained model through a Streamlit application.

The final application allows users to enter basic property characteristics and receive an estimated closing price.

---

## Dataset

The dataset consists of **CRMLS sold-property records** provided through IDX Exchange.

The modeling data cover:

- **January 2025 through June 2026**
- `PropertyType = Residential`
- `PropertySubType = SingleFamilyResidence`

The target variable is:

```text
ClosePrice
```

The original data contain property characteristics, geographic information, listing information, and transaction-related fields.

### Core Property Features

Examples of model features include:

- `LivingArea`
- `BedroomsTotal`
- `BathroomsTotalInteger`
- `LotSizeSquareFeet`
- `PropertyAge`
- `GarageSpaces`
- `Stories`
- `Latitude`
- `Longitude`
- `City`
- `PostalCode`
- `CountyOrParish`
- amenity indicators such as pool, fireplace, waterfront, and view

---

## Data Preprocessing

The preprocessing workflow includes:

### Property Filtering

Only California residential single-family residences are retained.

### Missing Values

Numerical missing values are handled using **median imputation**.

Categorical missing values are handled using the most frequent training category during model preprocessing.

Missingness indicators are also retained for selected variables such as:

- living area;
- bathrooms;
- lot size;
- year built;
- garage spaces;
- stories.

### Categorical Encoding

Categorical variables are converted into numerical representations using encoding methods appropriate for each model.

For the XGBoost model, categorical variables are transformed using **one-hot encoding**.

### Leakage Prevention

The following variables are excluded from modeling:

- `ListPrice`
- `OriginalListPrice`
- `ClosePrice_to_ListPrice_ratio`
- post-sale or transaction-derived fields
- listing identifiers

`ListPrice` and `OriginalListPrice` are excluded because they are unavailable for off-market properties and can introduce target leakage.

---

## Chronological Train/Test Design

Because the goal of the AVM is to estimate the current market value of a property, the project uses a **time-based evaluation strategy** rather than a random train/test split.

The most recent available month is reserved as the final test set.

For the final models:

```text
Training window: 15 months
Validation month: May 2026
Test month: June 2026
```

The 15-month training-window length was selected by comparing multiple rolling training windows using validation performance.

This approach better simulates production use, where the model predicts future property values using only historical information.

---

## Feature Engineering

Several additional features were evaluated during the feature-engineering stage.

These included:

- `DistrictName` from a school-district spatial join;
- `PropertyAgeSquared`;
- `BedBathRatio`;
- `LivingAreaPerBedroom`;
- `LivingAreaPerBathroom`;
- `LotCoverage`;
- cyclical monthly variables using sine and cosine transformations.

School-district information was generated by spatially joining property latitude and longitude coordinates with California school-district boundary data.

The expanded feature set slightly improved Linear Regression performance but did not improve the final Random Forest model. Therefore, both original and engineered feature sets were compared rather than assuming that additional features would always improve predictive performance.

---

## Models Evaluated

Four main regression approaches were evaluated:

1. **Linear Regression**
2. **Decision Tree Regressor**
3. **Random Forest Regressor**
4. **XGBoost Regressor**

Decision Tree and Random Forest hyperparameters were tuned using validation data.

For XGBoost, a light hyperparameter search was conducted over:

- `max_depth`;
- `learning_rate`;
- `n_estimators`.

The selected XGBoost configuration was:

```text
max_depth = 8
learning_rate = 0.10
n_estimators = 200
```

---

## Model Performance

All final models were evaluated on the unseen **June 2026** test set.

| Model | Test R² | Test MAE | Test MAPE | Test MdAPE |
|---|---:|---:|---:|---:|
| Linear Regression | 0.8240 | ~$244,911 | 22.50% | 15.91% |
| Decision Tree | 0.7654 | ~$254,213 | 19.69% | 13.08% |
| Random Forest | **0.8702** | **$174,078** | **13.11%** | **7.89%** |
| XGBoost | **0.8719** | $189,511 | 15.49% | 10.59% |

### Key Result

XGBoost achieved the highest test R²:

```text
Test R² = 0.8719
```

However, Random Forest produced lower MAE, MAPE, and MdAPE.

Therefore, XGBoost explains slightly more overall variation in closing prices, while Random Forest provides lower typical dollar and percentage prediction errors.

The results demonstrate why model selection should consider multiple metrics rather than R² alone.

---

## Expanded Evaluation

The Week 8 evaluation examined model performance beyond overall R².

For XGBoost, the June 2026 test results were:

```text
R²:      0.8719
MAE:     $189,511.45
RMSE:    $354,459.78
MAPE:    15.49%
MdAPE:   10.59%
```

Performance differed across property price ranges.

### Price-Band Results

The best price band by MAPE was:

```text
$750K–$1M
MAPE = 12.63%
```

The best price band by MdAPE was:

```text
$500K–$750K
MdAPE = 8.73%
```

The most difficult price band was:

```text
Under $500K
MAPE = 24.13%
```

These results suggest that the model performs more reliably for mid-priced properties, particularly homes between approximately **$500K and $1M**, while lower-priced properties remain more difficult to estimate accurately on a percentage basis.

## Streamlit Prediction Application

A simple Streamlit application was developed to demonstrate model inference outside a notebook environment.

Users provide:

- Living Area
- Bedrooms
- Bathrooms
- Lot Size

The application then:

```text
User Inputs
    ↓
Pandas DataFrame
    ↓
Saved Preprocessing Pipeline
    ↓
Trained XGBoost Model
    ↓
Predicted ClosePrice
    ↓
Streamlit Interface
```

The application loads previously trained model artifacts using `joblib` rather than retraining the model each time the application starts.

The deployed files include:

```text
week7_xgboost_model.joblib
week7_xgboost_preprocessor.joblib
week7_xgboost_metadata.json
```

Because the simplified Week 9 interface asks users for only four property characteristics, other model inputs are handled using preprocessing defaults learned from the training data.

The application should therefore be interpreted as a **simplified AVM demonstration**, rather than a complete location-specific appraisal system.

## Re-running the Analysis

The notebooks represent sequential stages of the modeling workflow.

They can be run in the following order:

```text
01_exploration.ipynb
        ↓
02_preprocessing.ipynb
        ↓
03_baseline_model.ipynb
        ↓
04_model_comparison.ipynb
        ↓
05_advanced_models.ipynb
        ↓
06_evaluation.ipynb
```

### Notebook Roles

**01_exploration.ipynb**

Performs exploratory data analysis of closing price, living area, bedrooms, bathrooms, and lot size.

**02_preprocessing.ipynb**

Handles missing values, categorical variables, feature preparation, and chronological modeling setup.

**03_baseline_model.ipynb**

Trains and evaluates the Linear Regression baseline.

**04_model_comparison.ipynb**

Compares Linear Regression, Decision Tree, and Random Forest models and evaluates feature engineering.

**05_advanced_models.ipynb**

Performs XGBoost hyperparameter tuning and evaluates the final advanced model.

**06_evaluation.ipynb**

Expands model evaluation using MAPE, MdAPE, price bands, prediction-error distributions, and other diagnostic metrics.

## Environment Compatibility

The saved model and preprocessing objects depend on the machine-learning libraries used during training.

In particular, the preprocessing pipeline was serialized using:

```text
scikit-learn 1.6.1
```

Using a substantially different scikit-learn version may cause compatibility problems when loading the saved `joblib` objects.

For Apple Silicon Macs, a native **ARM64 Python environment** is recommended when running XGBoost.

## Summary

This project demonstrates a complete machine-learning workflow for residential property valuation, from raw CRMLS transaction data through preprocessing, model development, evaluation, and deployment.

The best test R² was achieved by **XGBoost at 0.8719**, while **Random Forest produced the lowest MAE, MAPE, and MdAPE**. Expanded evaluation further showed that prediction accuracy varies across property price segments.

The final Streamlit application converts the trained AVM into an interactive prediction tool and demonstrates the transition from model development to practical machine-learning deployment.
